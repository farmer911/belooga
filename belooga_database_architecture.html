Sequence 2: Refresh Token Rotation & Thu Hồi Toàn Bộ Khi Bị Replay

Sử dụng SELECT FOR UPDATE để phát hiện và ngăn chặn token đánh cắp

100% 
sequenceDiagram
    autonumber
    participant App as FastAPI Auth Middleware
    participant DB as PostgreSQL 16
    participant SessTable as Table: refresh_sessions

    App->>DB: BEGIN TRANSACTION
    Note over App,DB: 1. Khóa dòng kiểm tra Token Hash
    App->>SessTable: SELECT * FROM refresh_sessions WHERE token_hash = $1 FOR UPDATE
    
    alt Token không tồn tại
        SessTable-->>App: NULL
        App->>DB: ROLLBACK
        App-->>User: 401 Unauthorized ("invalid_session")
    else Token đã bị Revoked trước đó (PHÁT HIỆN REPLAY ATTACK!)
        SessTable-->>App: Row (revoked_at IS NOT NULL)
        Note over App,DB: Bị tấn công lặp lại: Thu hồi toàn bộ family_id
        App->>SessTable: UPDATE refresh_sessions SET revoked_at = NOW()
WHERE family_id = $family_id AND revoked_at IS NULL
        App->>DB: COMMIT
        App-->>User: 401 Unauthorized ("session_compromised_all_revoked")
    else Token Hợp Lệ (Active)
        SessTable-->>App: Row (revoked_at IS NULL, expires_at > NOW())
        Note over App,DB: Đánh dấu thu hồi token cũ
        App->>SessTable: UPDATE refresh_sessions SET revoked_at = NOW() WHERE id = $current_id
        Note over App,DB: Cấp token mới thuộc cùng Family ID
        App->>SessTable: INSERT INTO refresh_sessions (identity_id, family_id, parent_id, token_hash, expires_at)
VALUES ($identity_id, $family_id, $current_id, $new_token_hash, $expiry)
        App->>DB: COMMIT
        App-->>User: 200 OK (New Access Token + Rotated HttpOnly Cookie)
    end

Payload: [{"id":"uuid-1","order":0},{"id":"uuid-2","order":1}]
    App->>DB: BEGIN TRANSACTION
    
    Note over App,DB: 1. Khóa tất cả các dòng của Profile để tránh xung đột
    App->>ExpTable: SELECT id, display_order FROM job_experiences
WHERE profile_id = $profile_id
FOR UPDATE
    ExpTable-->>DB: Acquired Exclusive Row Locks
    
    Note over App,DB: 2. Cập nhật hàng loạt (Batch UPDATE qua VALUES)
    App->>ExpTable: UPDATE job_experiences AS j
SET display_order = v.new_order, updated_at = NOW()
FROM (VALUES ('uuid-1'::uuid, 0), ('uuid-2'::uuid, 1)) AS v(id, new_order)
WHERE j.id = v.id AND j.profile_id = $profile_id
    ExpTable-->>DB: UPDATE 2 rows
    
    Note over App,DB: 3. Commit giải phóng Lock
    App->>DB: COMMIT
    DB-->>App: Success
    App-->>Client: 200 OK {"success": true}

Sequence 5: Thực Thi Truy Vấn Tìm Kiếm Ứng Viên (GIN Index Scan Plan)

Phân tích kế hoạch thực thi PostgreSQL Query Planner: Bitmap GIN Scan ➔ Heap Scan ➔ Join Media

100% 
sequenceDiagram
    autonumber
    participant API as FastAPI Search Router (/profile/search/)
    participant Planner as PostgreSQL Query Planner
    participant GIN as Index: ix_candidate_search_vector (GIN)
    participant Heap as Table: candidate_profiles (Heap)
    participant Media as Table: profile_media
    participant Skills as Table: profile_skills

    API->>Planner: SELECT p.id, p.first_name, p.last_name, p.headline, p.location,
 m.file_url AS video_url, array_agg(s.name) AS skills
FROM candidate_profiles p
LEFT JOIN profile_media m ON m.profile_id = p.id AND m.category = 'pitch_video'
LEFT JOIN profile_skills ps ON ps.profile_id = p.id
LEFT JOIN skills s ON s.id = ps.skill_id
WHERE p.is_hidden = false
 AND p.search_vector @@ to_tsquery('english', 'react & developer')
GROUP BY p.id, m.file_url
ORDER BY ts_rank(p.search_vector, to_tsquery('english', 'react & developer')) DESC
LIMIT 12 OFFSET 0;

    Note over Planner,GIN: 1. Sử dụng GIN Index để lọc nhanh các candidate khớp từ khóa
    Planner->>GIN: Bitmap Index Scan on ix_candidate_search_vector ('react & developer')
    GIN-->>Planner: Bitmap matching Page/Tuple IDs (vd: 42 candidates)
    
    Note over Planner,Heap: 2. Quét Heap dữ liệu & lọc điều kiện phụ
    Planner->>Heap: Bitmap Heap Scan on candidate_profiles (Filter: is_hidden = false)
    Heap-->>Planner: 38 visible candidates
    
    Note over Planner,Media: 3. Hash Left Join lấy video pitch thumbnail
    Planner->>Media: Index Scan on uq_profile_media_category (profile_id, 'pitch_video')
    Media-->>Planner: Matched Media URLs
    
    Note over Planner,Skills: 4. Left Join Kỹ Năng & array_agg(s.name)
    Planner->>Skills: Index Scan on profile_skills (profile_id)
    Skills-->>Planner: Matched Skills
    
    Note over Planner,API: 5. Sắp xếp điểm tương đồng (ts_rank) & cắt phân trang (LIMIT 12)
    Planner-->>API: 12 CandidateCardDTOs (Thời gian thực thi < 15ms)
